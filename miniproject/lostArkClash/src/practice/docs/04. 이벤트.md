## 1. 이벤트 모델

```
   사용자 동작              이벤트 객체              등록해 둔 리스너
  (버튼 클릭)  ────────►  ActionEvent  ────────►  actionPerformed(e) 호출
                                                  ↑
                         btn.addActionListener(리스너)  로 미리 연결해 둔다
```

**"이벤트 소스에 리스너를 등록해 두면, 사건이 생겼을 때 자바가 대신 불러 준다."**

---

## 2. 리스너 종류

| 리스너 | 메소드 | 언제 |
|--------|--------|------|
| `ActionListener` | `actionPerformed` | 버튼 클릭, 메뉴 선택, 텍스트필드 **Enter**, Timer |
| `ItemListener` | `itemStateChanged` | 체크박스·라디오·콤보 선택 변경 |
| `ChangeListener` | `stateChanged` | 슬라이더·스피너 값 변경 |
| `ListSelectionListener` | `valueChanged` | 리스트·표 선택 변경 |
| `DocumentListener` | `insertUpdate` 외 2개 | 텍스트 내용 변경 |
| `MouseListener` | `mouseClicked/Pressed/Released/Entered/Exited` | 마우스 클릭·진입 |
| `MouseMotionListener` | `mouseMoved`, `mouseDragged` | 마우스 이동 |
| `MouseWheelListener` | `mouseWheelMoved` | 휠 |
| `KeyListener` | `keyPressed/Released/Typed` | 키 입력 |
| `FocusListener` | `focusGained/Lost` | 포커스 이동 |
| `WindowListener` | `windowClosing` 외 6개 | 창 열기·닫기·최소화 |
| `ComponentListener` | `componentResized` 외 3개 | 크기·위치 변경 |

## 3. 세 가지 작성법

```java
// ① 익명 클래스 — 어떤 리스너든 가능
btn.addActionListener(new ActionListener() {
    @Override public void actionPerformed(ActionEvent e) {
        System.out.println("클릭");
    }
});

// ② 람다 — ⚠️ 메소드가 1개뿐인 인터페이스만 가능
btn.addActionListener(e -> System.out.println("클릭"));

// ③ 어댑터 상속 — 메소드가 여러 개인 리스너에서 필요한 것만
comp.addMouseListener(new MouseAdapter() {
    @Override public void mousePressed(MouseEvent e) { ... }
    // 나머지 4개는 안 써도 된다
});
```

**어댑터가 있는 리스너** (메소드가 여러 개라 람다 불가):

| 리스너 | 어댑터 |
|--------|--------|
| `MouseListener`, `MouseMotionListener` | `MouseAdapter` (둘 다 커버) |
| `KeyListener` | `KeyAdapter` |
| `WindowListener` | `WindowAdapter` |
| `FocusListener` | `FocusAdapter` |
| `ComponentListener` | `ComponentAdapter` |

💡 **어댑터란?** 인터페이스의 메소드를 전부 빈 몸통으로 미리 구현해 둔 추상 클래스. 상속해서 필요한 것만 오버라이드하면 된다.

## 4. 이벤트 객체에서 정보 꺼내기

```java
public void actionPerformed(ActionEvent e) {
    Object src = e.getSource();              // 이벤트를 일으킨 컴포넌트
    String cmd = e.getActionCommand();       // 버튼 글자 또는 setActionCommand() 값

    if (src == startBtn) { ... }
    switch (cmd) { case "시작" -> ...; }
}
```

**리스너 하나로 여러 버튼 처리하기:**

```java
class MyListener implements ActionListener {
    public void actionPerformed(ActionEvent e) {
        switch (e.getActionCommand()) {
            case "play"  -> clip.start();
            case "pause" -> clip.stop();
        }
    }
}
MyListener al = new MyListener();
playBtn.addActionListener(al);
pauseBtn.addActionListener(al);
```

## 5. 마우스 이벤트

```java
comp.addMouseListener(new MouseAdapter() {
    @Override public void mousePressed(MouseEvent e) {
        int x = e.getX(), y = e.getY();          // 컴포넌트 기준 좌표
        int clicks = e.getClickCount();          // 2 면 더블클릭
        if (SwingUtilities.isRightMouseButton(e)) { ... }
    }
    @Override public void mouseEntered(MouseEvent e) { ... }  // 마우스 올림
});

comp.addMouseMotionListener(new MouseAdapter() {
    @Override public void mouseDragged(MouseEvent e) { ... }  // 누른 채 이동
    @Override public void mouseMoved(MouseEvent e)   { ... }
});
```

⚠️ `mouseClicked` 는 **누른 자리에서 그대로 뗐을 때만** 발생한다. 조금이라도 움직이면 안 온다. 클릭 반응은 `mousePressed` 를 쓰는 게 안전하다.

💡 **라벨을 버튼처럼 쓰기:**

```java
label.addMouseListener(new MouseAdapter() {
    @Override public void mousePressed(MouseEvent e) { ... }
});
label.setCursor(new Cursor(Cursor.HAND_CURSOR));
```

## 6. 키 이벤트

```java
comp.setFocusable(true);              // ⚠️ 이게 없으면 키 이벤트가 안 온다
comp.requestFocusInWindow();

comp.addKeyListener(new KeyAdapter() {
    @Override public void keyPressed(KeyEvent e) {
        int code = e.getKeyCode();    // VK_LEFT, VK_A, VK_ENTER … (권장)
        char c = e.getKeyChar();      // 'a', 'A' … 문자키에만 의미 있음

        if (code == KeyEvent.VK_LEFT) { ... }
        if (e.isShiftDown()) { ... }  // isControlDown(), isAltDown()
    }
});
```

| 메소드 | 언제 | 특징 |
|--------|------|------|
| `keyPressed` | 키를 누른 순간 | 모든 키. **누르고 있으면 반복 발생** |
| `keyReleased` | 뗀 순간 | 모든 키 |
| `keyTyped` | 문자가 입력된 순간 | 문자키만. 화살표·F키는 안 옴 |

⚠️ 같은 리스너를 **중복 등록**하면 한 번 눌러도 여러 번 처리된다. 다시 등록하기 전에 `removeKeyListener()` 를 부르는 습관.

## 7. 포커스 — 키 이벤트가 안 오는 이유 1순위

**키 이벤트는 "포커스를 가진 컴포넌트"에게만 간다.** `JPanel` 은 기본적으로 포커스를 못 받는다.

```java
panel.setFocusable(true);          // ① 포커스를 받을 수 있게
panel.requestFocusInWindow();      // ② 실제로 달라고 요청
```

⚠️ **화면이 보이기 전에 요청하면 실패한다.** `CardLayout` 으로 막 전환한 직후가 딱 그 상황이라, 한 박자 미뤄야 한다.

```java
SwingUtilities.invokeLater(() -> requestFocusInWindow());
```

## 8. 💡 Key Binding — 포커스 문제 없는 키 처리

`KeyListener` 는 포커스 때문에 자주 말썽이다. Key Binding이 더 안정적이다.

```java
panel.getInputMap(JComponent.WHEN_IN_FOCUSED_WINDOW)
     .put(KeyStroke.getKeyStroke("SPACE"), "jump");
panel.getActionMap().put("jump", new AbstractAction() {
    @Override public void actionPerformed(ActionEvent e) { jump(); }
});
```

| 조건 | 언제 동작 |
|------|----------|
| `WHEN_FOCUSED` | 이 컴포넌트가 포커스를 가질 때 |
| `WHEN_ANCESTOR_OF_FOCUSED_COMPONENT` | 자식이 포커스를 가질 때 |
| `WHEN_IN_FOCUSED_WINDOW` | **창만 활성화돼 있으면** (게임에 적합) |

```java
KeyStroke.getKeyStroke("SPACE");
KeyStroke.getKeyStroke("ctrl S");
KeyStroke.getKeyStroke(KeyEvent.VK_LEFT, 0);
```

---

## ✅ 이 장 요약

- 리스너를 **등록해 두면** 자바가 불러 준다. 메소드 1개짜리는 람다, 여러 개면 어댑터
- `e.getSource()` / `e.getActionCommand()` 로 누가 일으켰는지 구분
- 클릭 반응은 `mouseClicked` 보다 `mousePressed` 가 안전
- 키가 안 먹으면 **포커스**를 의심. 게임이라면 아예 **Key Binding**
