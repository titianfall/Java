# 07. 스레드와 EDT

◀ 이전 [06. 대화상자와 꾸미기](06.%20대화상자와%20꾸미기.md) · [📚 목록](README.md) · 다음 [08. 함정과 빠른참조](08.%20함정과%20빠른참조.md) ▶

> Swing에서 가장 많이 헤매는 부분이다. 이 장만은 필요할 때 찾지 말고 **한 번 통독**하는 걸 권한다.

---

## 1. EDT란

Swing 프로그램에는 `main` 말고 **EDT(Event Dispatch Thread)** 라는 스레드가 하나 더 돈다.
이 스레드는 이벤트 큐에서 할 일을 하나씩 꺼내 처리한다.

```
[이벤트 큐]  버튼클릭 → 키입력 → 화면그리기 → repaint요청 → ...
                 │
                 ▼
        ┌──────────────────┐
        │       EDT        │  ← 이 스레드 하나가 전부 순서대로 처리
        └──────────────────┘
```

EDT에서 실행되는 것:
- 모든 **리스너** (`actionPerformed`, `keyPressed`, `mousePressed` …)
- 모든 **`paintComponent`**
- **Swing `Timer`** 의 콜백

---

## 2. 규칙 두 줄

> ### ① Swing 컴포넌트는 EDT에서만 건드린다.
> ### ② EDT를 오래 붙잡지 않는다.

**①을 어기면** — Swing은 thread-safe 하지 않다. 다른 스레드에서 `setText()`, `setLocation()` 을 부르면 화면이 안 갱신되거나, 절반만 그려지거나, 엉뚱한 좌표에 그려진다.
⚠️ **에러가 안 나고 조용히 이상해지는 게 최악이다.** "가끔 이상한데 재현이 안 되는" 버그의 정체가 보통 이것.

**②를 어기면** — EDT가 큐를 못 비우니 **창 전체가 얼어붙는다.** 버튼도 안 눌리고 화면도 안 그려진다.

```java
// ❌ 이러면 3초 동안 창이 완전히 멈춘다
btn.addActionListener(e -> {
    Thread.sleep(3000);
    label.setText("완료");
});
```

→ 리스너 안에서 **`Thread.sleep()`, 무거운 파일 읽기, 무한 루프 금지.**

---

## 3. EDT로 작업 넘기기

```java
// 다른 스레드에서 UI를 건드려야 할 때 — 큐에 넣고 바로 반환 (비동기)
SwingUtilities.invokeLater(() -> {
    label.setText("갱신");
});

// 끝날 때까지 기다려야 할 때 (동기)
SwingUtilities.invokeAndWait(() -> { ... });   // ⚠️ EDT 안에서 부르면 예외

// 지금 내가 EDT인가?
boolean isEdt = SwingUtilities.isEventDispatchThread();
```

### 💡 예외: `repaint()` 와 `revalidate()`

이 둘은 **아무 스레드에서 불러도 안전하다.** "다시 그려 달라"는 요청만 큐에 넣고 바로 돌아오기 때문이다. 실제 `paintComponent()` 는 나중에 EDT가 부른다.

```java
hp -= damage;   // 데이터만 바꾸고
repaint();      // 그리기는 EDT에게 맡긴다   ← 이 패턴이 안전하다
```

**그래서 커스텀 드로잉이 유리하다.** `JLabel.setText()` 를 다른 스레드에서 부르는 건 위험하지만, "필드 값만 바꾸고 `repaint()`" 는 안전하다.

## 4. Swing Timer — 주기 작업

```java
import javax.swing.Timer;          // ⚠️ java.util.Timer 아님!

Timer timer = new Timer(1000, e -> {          // 1000ms 마다
    count++;
    label.setText("" + count);                // 콜백이 EDT에서 도니까 안전
});
timer.start();
```

```java
timer.stop();
timer.restart();
timer.setDelay(500);
timer.setRepeats(false);                      // 한 번만 (지연 실행)
timer.setInitialDelay(2000);                  // 첫 실행까지 대기
```

| | `javax.swing.Timer` | `java.util.Timer` |
|---|---|---|
| 콜백 실행 스레드 | **EDT** | 별도 스레드 |
| Swing 컴포넌트 조작 | 안전 | 위험 |
| 용도 | GUI 애니메이션 | 백그라운드 작업 |

**GUI에서는 항상 `javax.swing.Timer`.**

⚠️ `import java.util.*;` 와 `import javax.swing.*;` 를 같이 쓰고 `Timer` 를 쓰면 **어느 쪽인지 모호해서 컴파일 에러**가 난다. 명시적으로 import 할 것.

### 애니메이션 기본형

```java
// 초당 약 60번
new Timer(16, e -> {
    x += speed;                    // 상태 갱신
    if (x > getWidth()) x = 0;
    repaint();                     // 다시 그리기
}).start();
```

## 5. SwingWorker — 오래 걸리는 작업

파일 다운로드처럼 시간이 걸리는 일을 EDT를 막지 않고 하는 방법.

```java
new SwingWorker<String, Integer>() {          // <최종 결과 타입, 중간보고 타입>

    @Override
    protected String doInBackground() throws Exception {   // 백그라운드 스레드
        for (int i = 0; i <= 100; i++) {
            Thread.sleep(50);
            publish(i);                       // 중간 진행률 보고
        }
        return "완료";
    }

    @Override
    protected void process(List<Integer> chunks) {   // EDT에서 실행
        progressBar.setValue(chunks.get(chunks.size() - 1));
    }

    @Override
    protected void done() {                   // EDT에서 실행
        try { label.setText(get()); } catch (Exception e) { }
    }
}.execute();
```

| 메소드 | 실행 스레드 | 하는 일 |
|--------|------------|---------|
| `doInBackground()` | 백그라운드 | 오래 걸리는 일. UI 조작 **금지** |
| `publish(v)` | 백그라운드에서 호출 | 중간 결과를 `process` 로 전달 |
| `process(list)` | **EDT** | 진행 상황을 UI에 반영 |
| `done()` | **EDT** | 끝난 뒤 마무리. `get()` 으로 결과 받기 |

## 6. 직접 스레드를 쓸 때

정말 필요하면 이렇게 쓴다.

```java
private volatile boolean running = true;   // ⚠️ volatile 없으면 못 멈출 수 있다

Thread t = new Thread(() -> {
    while (running) {
        try {
            Thread.sleep(100);
        } catch (InterruptedException e) {
            return;                        // 인터럽트되면 종료
        }
        x += 1;                            // 데이터만 바꾸고
        panel.repaint();                   // repaint 는 안전
    }
});
t.start();

// 멈추기
running = false;
t.interrupt();
```

⚠️ **`volatile` 이 왜 필요한가** — 각 스레드는 성능을 위해 변수를 자기 캐시에 들고 있을 수 있다. `running = false` 로 바꿔도 도는 쪽이 영원히 못 볼 수 있다. `volatile` 은 "항상 메인 메모리에서 읽어라"는 표시다.

⚠️ **끝난 스레드는 재사용 불가.** 다시 `start()` 하면 `IllegalThreadStateException`. 새로 만들어야 한다.

⚠️ **`Thread.stop()` 은 쓰지 마라.** deprecated이고 자물쇠를 잡은 채 죽어서 상태가 깨진다.

### 스레드 상태

```
   new Thread()          start()              스케줄러가 선택
      NEW      ────────► RUNNABLE ◄──────────────────┐
                            │                        │
       sleep(ms) / wait(ms) │                        │ 시간 만료 / notify()
                            ▼                        │
                     TIMED_WAITING ──────────────────┤
                            │                        │
                     wait() │                        │
                            ▼                        │
                        WAITING ────────────────────-┘
                            │
              run() 끝 / 예외│
                            ▼
                        TERMINATED   ← 다시 start() 못 한다
```

### `wait` / `notify`

```java
synchronized (lock) {
    while (조건이 아직 아님) {   // ⚠️ if 가 아니라 while
        lock.wait();            // 자물쇠를 놓고 잠든다
    }
    // 일한다
}

synchronized (lock) {
    조건 = true;
    lock.notifyAll();           // 자고 있는 스레드를 깨운다
}
```

| 실수 | 결과 |
|------|------|
| `synchronized` 밖에서 `wait()`/`notify()` | `IllegalMonitorStateException` |
| `if (조건) wait()` | 가짜 깨어남(spurious wakeup)으로 조건이 아닌데 진행 |
| `notify()` 를 `notifyAll()` 대신 | 엉뚱한 하나만 깨어 나머지가 영원히 잠듦 |
| `wait()` 전에 `notify()` 가 지나감 | 신호를 놓쳐 영원히 대기 (lost wakeup) |

## 7. 💡 그런데 스레드가 정말 필요한가?

"일정 시간마다 값을 조금씩 바꾸고 다시 그리기"라면 **Timer 가 훨씬 낫다.**

| | 스레드 여러 개 | Timer 1개 |
|---|---|---|
| EDT 안전성 | ❌ 직접 챙겨야 함 | ✅ 콜백이 EDT에서 실행 |
| 일시정지 | 플래그 + `wait/notify` | `timer.stop()` |
| 재개 | 플래그 + `notifyAll()` | `timer.start()` |
| 종료 | `interrupt()` + 참조 정리 | `timer.stop()` |
| 코드량 | 스레드 클래스마다 반복 | 없음 |

스레드가 어울리는 경우는 **오래 걸리는 단발 작업**(파일 로딩, 네트워크)이고, 그건 `SwingWorker` 가 담당한다.

---

## ✅ 이 장 요약

1. **UI는 EDT에서만.** 다른 스레드에서 건드리면 에러 없이 조용히 깨진다
2. **EDT를 붙잡지 마라.** 리스너 안에서 `sleep`·무한루프 금지
3. **`repaint()`/`revalidate()` 는 예외** — 어디서든 안전. "값 바꾸고 `repaint()`" 패턴을 쓰자
4. 주기 작업은 **`javax.swing.Timer`**, 오래 걸리는 일은 **`SwingWorker`**
5. 직접 스레드를 쓰면 **`volatile`**, `wait` 은 **`while`** 안에서
